# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a static HTML project with no build system or package manager. All HTML files are standalone pages that open directly in a browser. The only non-page files are `usage-dashboard.js`, a zero-dependency Node.js script (Node 18+) that renders a terminal usage dashboard (no local-server mode), and `golf-tracer.py`, an offline Python/OpenCV script that burns a ball-flight tracer into a swing video — plus `yotei.webmanifest` and its home-screen icons in `assets/` (`yotei-icon-180/192/512.png`), which only exist so `yotei.html` can be added to a phone's home screen.

- **`golf.html`** — Golf swing analyzer (高爾夫球軌跡追蹤). Primary flow is **automatic**: drop any phone swing video (typically 30/60 fps, shot from behind) and the page finds the swing, the teed ball, the impact moment and the top of the backswing, estimates club-head speed from downswing time (tempo model), tracks the ball streak when visible, and simulates the flight (carry, apex, time) with a tracer overlaid on the video through a camera model built from the file's own lens metadata. A collapsed **manual** section keeps the face-on slow-motion measurement tools (pixel scale from club length, frame-by-frame ball/club marking, least-squares fits). Video never leaves the browser.
- **`golf-tracer.py`** — Offline shot-tracer CLI (Python 3 + `opencv-python-headless numpy pillow imageio-ffmpeg`, not part of the site). For normal-speed 30/60 fps swing videos, typically shot from behind, where the ball leaves the frame in a few frames: `python3 golf-tracer.py video.mov --impact <frame> --tee <x,y>` tracks the ball streak with consecutive-frame positive differencing, fits a perspective-linear model `p(t) = (A + B·t)/(1 + c·t)` through the tee, extrapolates (dashed, with a linear image-space gravity droop) for up to 1.2 s, aligns the trail to hand-held camera motion with ORB + RANSAC similarity to the impact frame, and writes an H.264 mp4 (original audio kept, 0.25× slow-mo replay appended) via the ffmpeg binary bundled in `imageio-ffmpeg`. Tracking stops on implausible jumps, on deviation from the fitted model (after 6 frames) or when the streak area grows (a receding ball only shrinks) — the usual failure is latching onto the golfer's head. It cannot measure ball speed (no depth from a rear view); `--dry-run` prints tracking/fit only, `--stills` saves frames as JPEG.

## Architecture

### `index.html` (任意門 hub)
Product truth: the 「Site hub」 section of `PRODUCT.md`; dev-only direction contract: `.impeccable/surfaces/index-html.md`; design record: `DESIGN-hub.md` + `.impeccable/design-hub.json` (root `DESIGN.md` is the trip's system — the two pages are separate worlds). Single file, no dependencies, no state, no localStorage.

Structure: `header.sky` (flat sky, authored SVG clouds kept in a band above the title on ≥760px, `h1.title` 「我的小工具」, `.lede`, SVG `.horizon`) → `main.field` (flat grass with two offset tuft-pattern layers) → one `section.lot.lot-{travel|games|sports|notes}` per group: `.sign` (SVG stake sign + `h2.sign-text`), the SVG concrete `.pipes` in the first lot only, and `.ground` (a flat `svg.dirt` patch) holding `ul.doors > li.spot > a.door` (two columns on phones, `auto-fit` 188px columns at ≥760px, even doors staggered down) → fixed `#flash` overlay. No footer. **To add a tool:** copy one `li.spot` into the right lot, set `href`, the nameplate name and `.door-desc` line as phrase segments (`span.seg`, inline-block: a CJK line may only break between segs; a seg ends with its ` ·` separator; a Latin–CJK space sits between segs, outside the spans), the icon `<use href="#i-…">` (add a `<symbol>` to the sprite for a new icon: 24-unit grid, 1.8 stroke), update the door count in `.lede` and the meta description, then run `python3 tools/trip-font.py --page index.html`. The title and lot names use `'Zen Maru Heavy'` (Zen Maru Gothic Black, a fixed `unicode-range` subset of 我的小工具旅行遊戲運動理財與筆記) — a new lot name needs a new subset.

A door: `.door-body` > `.door-frame` (deep pink, `perspective`) > `.door-way` (the light behind the door: flat white, no gradient or glow) + `.door-panel` (pink, `transform-origin: left`, `.mold-top/.mold-bot` mouldings, `.knob`, white `.plate` with icon + name) + `.door-shadow` (flat brown ellipse at .35 opacity, behind the door via `isolation: isolate`); `.door-desc` sits on the dirt below. Hover/focus opens the panel a crack (`rotateY(-26deg)`). JS: a plain click (no modifier, left button) calls `preventDefault`, adds `.is-opening` (panel to `rotateY(-84deg)`, a sliver on the hinge side), sets `#flash`'s `--x/--y` to the doorway centre, grows its `clip-path` circle at 300 ms and navigates at 720 ms; modified clicks and `prefers-reduced-motion` navigate immediately. A `pageshow` handler closes every door again because the Back button restores the page from bfcache mid-animation. All text is navy `--ink` (≥6.5:1 on sky, grass and dirt); everything is cel-flat — no gradients, no glow shadows.

### `trip.html` (station edition)
Product truth: the trip sections of `PRODUCT.md`; dev-only direction contract: `.impeccable/surfaces/trip-html.md`; design record: `DESIGN-livecam.md` + `.impeccable/design-livecam.json` (it shares livecam's station world; root `DESIGN.md` now records the booklet in `trip-v2.html`). Generated once from `trip-v2.html`'s content, then maintained by hand — edit `trip.html` directly.
- **Order:** top bar (出口 → `index.html`, title, v2 / v1 keys, theme) → `.top` grid: `header#cover.hero` (LED board: trip name, dates, route, the big red countdown / today number; then the `a#due` 下一個期限 row before the trip; keys 今天的行程 / 日程表 / 行前準備 n/15), `nav#contents.map` (構內圖: facility tiles + `.island` platforms, each `a.trk[data-day]` links to its day), `section#plan` (日程表: the LED 發車時刻表 rows `#planRows li[data-day]` inside `details#planFold`, folded below 700px and re-laid out with `LED.refresh()` when opened; there is no flights section — `#flight-info` is D1's 12:50 departure ticket) → sticky `nav.tabs` (scroll-spy over `[data-tab]`) → `main`: `article.day#day-1…8` (`header.band` = `.eki` 駅名標 with prev / next platforms + `h2.band-title`; then the trip-v2 day body: `.promises` tickets, `.prose`, `.meal`, `.box` / `.box.must`, `.appendix` slips, `button.stamp`; lodging is the 宿 ticket — only D6/D7 keep a `宿：…` `.box` line, and the `.bed` plate is gone) → `#stay`, `#transport`, `#food`, `#pretrip-checklist` (facility zones, `header.band.zone`) → `footer#back` (出口). Every id of trip-v2 still exists; `#overview` / `#days` are aliased in JS.
- **Day data:** each day's line colour and station sign come from the generator's place table (橫濱 / 江之島 / 鎌倉 YS sky blue, 河口湖 HF orange, 新宿 / 銀座 / 澀谷 / 成田 TK yellow-green — livecam's line codes) and the `DAYS` constant in the script (number, date, weekday, title, place, lodging) drives the LED boards — **when a day's title or lodging changes, edit the platform section, the `.trk` row in the map, the `#planRows` row and `DAYS`, then run `tools/led-glyphs.py --page trip.html` and `tools/trip-font.py`.**
- **Red is a promise:** tickets (`.stub-booked/-due/-opens` times), station-stamp `.hanko` in red (已預約 / 期限 / a date; dashed red 還沒訂 when booking opens later — a to-do 還沒訂 and 待確認 are dashed ink), `.box.must`, the `#due` row, today's marks. D2–D5's hour-by-hour plans live in the faint 時間軸估算 slips (D5's afternoon chain moved out of its prose on 2026-10-06); other days' prose still cites times in passing — put any new schedule in a slip, not in prose. Line colours are bands, rings and rails only.
- **Checklist:** 15 rows in four `.ck-group`s (有期限 / 出發前辦好 / 打包 / 當天再看, each with its own `.ck-n` count; ticks in `.ck-keep` = 當天再看 do not strike through). Each `li` has the anchor `ck-<data-ck>`. The `DUES` list in the script (date, label, checklist id, `done`) drives the `#due` row — **livecam.html carries an identical copy; change both together**: the first deadline that is not `done`, not past and not ticked; **when a deadline is handled (e.g. the Z test drive is booked), set its `done: true`** — ticks live on one phone, the page is shared by both travellers, and a done deadline also starts ticked on every phone. Add a dated task there and in the 有期限 group together.
- **Ticket actions:** a ticket for a place ends with `.stub-acts` keys (`a.sk`, 44px): 地圖 (Google Maps search URL), 撥號 (`tel:`, only numbers confirmed on official pages; Hotel BUSTEL has none) or 時刻表. Phone numbers in running text are `a.lnk` tel: links.
- **State:** checklist localStorage `trip-checklist-v1` keyed by `data-ck` (same ids as v1 / v2 plus `vjw-checkin`; `d4-timing` was merged into `car-return` on 2026-10-06; add new ids, never renumber), stamps `shiori-stamps-v1`, theme `tk_theme` (shared with livecam). `.is-offline` hides embedded maps. Print opens every slip.
- **LED:** the same renderer as livecam (`LED.Row`, plus a `scale` option for the countdown digits); reduced motion wraps rows instead of scrolling. Promise rows (`#due`, `.now-led`) never scroll; they wrap. On today's platform the `.now-led` strip under the 駅名標 (label 下一個約定 / 次の約定) shows the next ticket and the time left (還有 N 小時 N 分, red in the last two hours) with an `HH:MM` time (Japan time, refreshed every 30 s; red time for booked / due / opens; a ticket printed in Taiwan time, like D1's 12:50 departure, gives its Japan time in `data-jst`) — and past tickets get `.is-past` (plain ground, dashed edge, 「· 已過」, text kept at full contrast). It draws `.stub-what` text, so `tools/led-glyphs.py --page trip.html` also counts ticket subjects.
- **Slips:** heads are facility keys (charcoal icon square, key-style chevron); 導航節點 slips are `ol.stops` route diagrams on the day's line colour (`li.major` = main stop, `.nt` = note); 時間軸估算 slips are `.tt` station timetables (時 / 分 / 行程, rows grouped by hour, still `.faint` and collapsed).

### `trip-v2.html` (旅のしおり)
The second version, frozen on 2026-10-01 when the station edition replaced it (it was `trip.html` until then; its old direction contract is in git history of `.impeccable/surfaces/trip-html.md`). The visual system is root `DESIGN.md` + `.impeccable/design.json`. Documented below for reference; do not add content here.

Structure, top to bottom: `header.cover#cover` (vertical title, countdown/today stamp, actions) → `nav.tabs` (sticky index tabs, one per page, coloured by paper stock) → `main`: `#contents` 目錄 → `#plan` 日程表 (8 rows + `#flight-info` stubs) → `article.sheet.day#day-1…8` → `#stay` (`#stay-d1…d5`) → `#transport` (`#transport-rental/-nex/-drive/-tokyo`) → `#food` (`#food-odawara/-kawaguchiko/-shonan/-shinjuku/-ginza/-shibuya`) → `#pretrip-checklist` → `footer#back` (phone numbers, links, memo lines). Old tab hashes `#overview`/`#days` are aliased in JS; every other old anchor id still exists.

Two inks only: `--ink` (Federal Blue) prints all text and rules; `--red-ink`/`--red` print hard commitments only (booking times, deadlines, 予約済/締切 hanko, stamps). ### `golf.html`
Single-file app, two IIFEs. The first (manual module) owns the `<video>`, the `#view` canvas, frame seeking, the manual marking tools and the physics; it exposes `window.__golf = { state, simulate, seekTo, runSim, render, CLUBS, AERO, … }` and calls `window.__golfOverlay(ctx, scale, currentTime)` at the end of every `render()`. The second (auto module, `window.__golfAuto`) listens to the same `#file` input and runs the automatic pipeline, drawing its trail through that hook. GSAP core only for the entrance stagger (guarded `typeof gsap`, page works without it). Fonts from Google Fonts; no Tailwind.

**Auto pipeline** (`run(file)` in the second IIFE), designed for hand-held 30/60 fps rear-view clips where the ball is visible for only a few frames:
- **Metadata** (`readQtMeta`): walks the MOV/MP4 atoms with `File.slice` (top level → `moov` → `meta`/`udta/meta` and every `trak/meta`), decoding QuickTime `keys` + `ilst` (types 1 string, 21/22 int, 23/24 float). iPhone files carry `com.apple.quicktime.camera.focal_length.35mm_equivalent` and `…model` on the video track; `f_px = diag_px × f35 / 43.27`, default 27 mm when absent.
- **Capture** (`capturePass`): plays the video once (muted) with `requestVideoFrameCallback`, storing every presented frame as gray at 640 px on the long side (480 for clips longer than 8 s) with its `mediaTime`. If >5 % of frame intervals are irregular (dropped frames) it replays at 0.5× then 0.25×; `fps` comes from the median frame interval (10th percentile when frames were dropped), snapped to common rates (24/25/30/48/50/60/100/120/240) within 8 %. A watchdog resolves the capture if `ended` never fires. Fallback without rVFC: seek-stepping at 30 fps. `state.busy` on the manual module is held while this runs. The `<video>` is kept in layout at 2×2 px / opacity 0.01 rather than `display:none` (iOS Safari does not decode frames of a hidden video).
- **Motion energy** (`motionEnergy`): pass 1 accumulates per-row motion over the whole clip to find the golfer's **active band** (`A.band`: rows with >10 % of the peak row motion; framing varies — a far golfer may occupy only the upper half above a bright pebble floor). Pass 2 gives per frame the % of pixels with |Δ| > 25 vs the previous frame for the whole frame (`E`, 3-frame smoothed `sm`) and for the impact zone = lower 40 % of the band (`El`).
- **Swing bursts** (`swingBursts`): lower-region bursts that follow a dip (min of `sm` in the 0.15–0.8 s before); `quietOK` marks bursts whose dip is preceded (≤1.6 s) by a ≥0.15 s quiet stretch (`sm < 0.6`) — a real address→backswing→top→impact shape.
- **Ball** (`findBall`, async — yields between windows so the progress bar keeps moving on phones): in the temporal median image (≤12 sampled frames, typed-array insertion sort, lower 70 % of the frame only) of each burst's backswing window (plus seven generic 20 % windows) find bright (>165), locally contrasted (+35 over a 15×15 box blur), small, round blobs between 40 % down the active band and 15 % below it (the teed ball sits at the golfer's feet). For each, a brightness series = 7×7 local max (tolerates hand-held drift), then *vanish events* = ≥0.35 s present run followed by 3 absent frames. Accept only events at the burst (±8 frames), with a **one-frame drop ≥0.7** of the contrast, or a two-frame drop ≥0.875 since at 30 fps the exit can straddle two exposures (only a struck ball leaves a 7×7 window that fast; feet/gloves fade over several frames), with the window **reverting to background** afterwards (occluders such as a leg make it darker → rejected), and mostly absent for 1.5 s. A vanish also needs a **pause before it** (motion-energy dip < 0.8, or < 0.35× the preceding backswing peak, in the 0.15–0.8 s before) — a glove moving mid-backswing has none. Score = sharpness + swing-structure + persistence + lower-band position − edge penalty; `findBall` returns the ranked candidate list (`A.ballCands`) and `run()` **validates the top 3 by streak tracking**: the first whose streak tracks ≥3 frames, ends ≥20 px above the tee, spans ≥60 px and whose first streak is ≥ max(40 px, 3× ball diameter) long wins (an occluded bucket or a shoe never produces such a streak); if none validates the best-scored candidate is kept. `impact frame = d − 1` (d = first absent frame). `A.ballDebug` records every candidate and its rejection reason; `A.trailDebug` records the search window and top components per tracked frame. Fallback impact (`fallbackImpact`) when no ball: strongest burst with a quiet address before its dip.
- **Timing** (`findTopAndStart`): top of backswing = centre of the flat minimum of `sm` 0.15–0.8 s before impact; backswing start = end of the last quiet stretch before it. Club-head speed (mph) = `27.5 × clubFactor / T_down` (tour ≈ 0.25 s ≈ 110 mph, amateur 0.3–0.4 s). Launch = club typical + 0.06° per mph below the club's typical speed (clamped −2/+6), spin = club typical × clamp(speed ratio, 0.9, 1.3). Nudge buttons shift impact/top by one frame and re-estimate.
- **Full-res refinement**: `grayAt(t)` seeks to `t + 0.4/fps` (a frame's exact presentation time can resolve to the previous frame, which made consecutive diffs empty). `refineBall` seeks 4 frames before impact and measures the ball centroid + equivalent diameter; `trackStreak` seeks impact+1…+30 and tracks the positive-diff streak (first streak must start within 90 px × 60/fps of the tee — at 30 fps the ball has flown ~1.5 m before the first exposure — and sit above it; at ≤35 fps the diff threshold drops to 14 and the mask is dilated 1 px to bridge the faint, fragmented streak, with a 50° direction tolerance for the first two steps; then velocity prediction with 0.8 decay (candidates scored direction-aware for the first 6 points: perpendicular offset from the flight line counts fully, along-track error ×0.4, plus a penalty for components far smaller than the previous streak; the second step may be up to 2.6× the first because the first streak's centroid sits mid-exposure), a perspective-linear model `p(t) = (A + B t)/(1 + c t)` after 6 points; stops on implausible steps, direction changes >35°, growing area or model deviation >40 px). Frames 1–3 may be skipped if the club head masks the streak.
- **Camera motion** (`estimateShifts` / `shiftAt`): for frames impact−1.2 s … +3.5 s, the translation of each analysis-res frame relative to the impact frame by coarse-to-fine SAD block matching (whole frame at 1/8 ±6 px, then the median over 3×4 blocks at 1/4 ±2 px — the median ignores the moving golfer). Every overlay point (tee, trail, projected path) is drawn in impact-frame coordinates plus this shift, so the tracer follows hand-held panning. Translation only; 4-px quantisation at analysis resolution.
- **Camera model** (`cameraModel`): distance to ball `Z0 = f × 0.04267 / ball_px` (accepted 1–15 m), pitch from the ball's image position with an assumed camera height (`#autoCamH`, default 1.2 m); `solveAzimuth` finds the horizontal launch direction whose projected velocity matches the streak direction (needs ≥3 trail points), `project()` maps the simulated 3-D path (x downrange, y up, z right) into the frame. A geometric ball speed from the first streak is shown only as a cross-check (very sensitive to f and sub-frame timing).
- **Output**: tiles in `#autoCard`, an energy timeline canvas with 起桿/頂點/擊球 markers, the estimate pushed into the manual simulator (`G.runSim()` → charts), `▶ 播放 Tracer` plays impact−1 s … +3 s on the `#view` canvas with the measured trail (solid) and the projected simulation (dashed) plus glow; the static overlay via `__golfOverlay` shows the same on any frame at/after impact. HEVC that the browser cannot decode surfaces as a status warning pointing to Safari / 最相容 format.
- **Frames**: hidden `<video>` (muted, playsinline) drawn onto an offscreen full-res canvas (`frameCanvas`, `willReadFrequently`), then scaled onto the visible `#view` canvas with overlays. Frame N is reached by seeking `currentTime = (N + 0.5) / playFps` and waiting for `seeked`. Two fps settings: **播放幀率** (`playFps`, used for stepping) and **拍攝幀率** (`captureFps`, used for real time — slow-mo exports play at 30 fps but each frame is 1/240 s). `impactFrame` anchors `k = 0`; if unset, the first ball mark is used.
- **Scale**: two clicks on a known length (club-length presets or custom) → `scale.mPerPx`. Every metric readout requires it.
- **Marks**: `ballPts` / `clubPts` are `Map<absFrame, {x, y, auto}>` in video pixels. Click modes (`scale` / `ball` / `club` / `none`) via `[data-mode]` buttons; switching mode scrolls the canvas back into view if it is off-screen.
- **Auto-tracking** (`autoTrack` → `detectBlob`): frame differencing between consecutive full-frame `ImageData` within a search window around the predicted position (`2·last − before` when two points exist, else `last`), threshold → 4-connected components → filter by area (derived from the ball radius in px) → score = distance to prediction + polarity penalty (auto-detected bright/dark object vs surroundings, or forced via `#polarity`) + size-similarity penalty for the ball. The blob at the previous position (ghost) is excluded. Club mode uses `anchorBottom`: the centroid of the component's bottom band only, so the moving shaft doesn't drag the point up. A step whose displacement is wildly inconsistent with the previous one stops tracking and asks the user to correct by clicking. Marking two consecutive frames manually before auto-tracking is the recommended flow (the follow-through club head competes with the ball in the first frames).
- **Fits**: `fitBall` — least squares `X = vx·t`, `Y = vy·t − ½gt²` through the first tracked point → `v0`, `launch`, `dirSign`, RMS residual. `fitClub` — mean speed over the last ≤3 intervals before impact and attack angle from the last interval; then estimates ball speed / launch / spin from the `CLUBS` table (Trackman tour averages: smash factor, launch, AoA, spin, ball speed) scaled by measured club speed and AoA.
- **Simulation** (`simulate`): RK4 at 5 ms, drag `Cd = 0.20 + 0.50·S`, lift `Cl = 0.14 + 0.80·S` with spin ratio `S = rω/v` capped at 0.35, spin decay τ = 25 s (`AERO`). Calibrated to Driver 71.5 m/s / 11° / 2700 rpm ≈ 260 yd and 7i 53.6 m/s / 16.5° / 7000 rpm ≈ 166 yd. Axes: x downrange, y up, z right; positive spin-axis tilt curves right. This matched a 4,000-week simulation to 0.6 pp per category on average — keep it analytic, the old 500-week sampler was too noisy to rank the middle of the league or judge 0.1-category trades. `setWaiverLevel()` builds the 自由球員水準 projection from the 20 best undrafted players; because the league is active, any player whose `bv` (non-punt value) is below it is simulated as that waiver-level player, and two thirds of each player's missed games are whole weeks filled by it (IL). `leagueTable()` → per team `w` (average categories won per week vs the other 13), `m = 2w − 9`, `cat[]`, `rank[]`, `vs[j]` (weekly margin vs team j) and `power`. `evalTrade()` (rosters refilled/trimmed to 14 with `fitRoster()`), `swapGain()` and `pickupGain()` are what the trade calculator and suggestions use.
- **League mode** (`leagueMode()` = `state.draft === DRAFT_ID`): on load, a save whose `draft` differs from `DRAFT_ID` (or an old auction-era save) is replaced by `draftSold()`. `state.sold[id] = {p, m, t}` where `t` is the team index (`m` = `t === DRAFT_ME`); a free agent has no entry. `computeLeague()` groups `state.sold` by `t`, fills short rosters from the best free agents and builds `lg.table`; `scheduleLeague()` reruns it (next tick) after any roster change. `body` carries `is-league` / `is-auction`, and `.league-only` / `.auction-only` elements are shown or hidden by `renderModes()`. Rows show the owner and an 改隊伍 select (`commitOwner`, which offers an undo toast and returns focus to the row's key via `focusRowEdit()`); my team panel (`renderTeam()`) shows `#rankPill` (第 N 名／14 隊, violet for the top 3, red for the bottom 3), `#tlSum` (the weekly record as the 62px number with its label, $/week in green or red with 每差一類 $60 · 例行賽 20 週約 …), the nine category ranks (`#tlRanks`: `.cat` cells, `.weak` red tint + 要補, `.strong` blue + 前三), the 最難打 line (`#tlCoach`), my roster rows with draft price and value (`#teamList`, `.mstrip`: name over team · position, a 44px × that sends the player to the free agents) and the margin vs every team (`#tlVs`, in `#vsZone`); in auction mode `#auctionStats` shows the budget left and the max bid as the two big numbers, then one line with spots, league money and inflation, above the bought players. Undo toast: `offerUndo(msg, snapshot, focus, back)` shows `#toast` for 9 s with 復原 (restores the `state.sold` snapshot) and ×; a keyboard × moves focus to 復原, and after 復原 `back()` returns focus to the restored row once the league recompute has rendered (`lg.after`, run at the end of `scheduleLeague()`'s timer). 交易試算 (`tr`): partner select (13 teams + 自由球員), give/get checkboxes; `#tradeResult` (`.tres`, its own `tres` container) opens with `.deal` — each side a label plus `.pchip` player chips (44px; tapping one, `data-unpick`, takes him out of the deal) with a swap icon between the sides, one row per side below a 520px container — then the verdict (`.verdict`: 換完你每週 +$N with 整季 +$M), the box score `table.bx` (both teams in the same columns: 平均每週 換前 → 換後 and the weekly 類 change; only the partner's row adds its $, because mine is the headline), the nine `.dc` cells under 九類勝率變化 (the change in weekly win rate as the big number, → the new rate under it, 13.5px on wide result columns, 11px at ≤ 400px, the arrow dropped at ≤ 300px), notes and 套用 / 清除勾選. `revealChecked()` keeps each list's first checked row scrolled into view and `tryTrade()` scrolls the result to the top of the screen, so the deal and the verdict share one viewport. 套用 moves only the checked players (one-level in-memory undo) and leaves the receipt (`tr.receipt`, `receiptHTML()`: 已套用這筆交易, who went where, 平均每週 / 每週輸贏 / 弱項 before → after, 復原這筆交易) until the next pick; `paintResult()` replaces the result's HTML and keeps keyboard focus (the receipt heading after 套用, the hint after 復原, the same button after a recompute); `#tradeSay` (polite live region) announces the verdict and the receipt. 還原成 10/5 名單 (`ROSTER_ASOF`) is two-step. ## Impeccable (design skill + hooks)

[Impeccable](https://github.com/pbakaus/impeccable) is installed at project scope for Claude Code: the skill in `.claude/skills/impeccable/`, four `impeccable-*` subagents in `.claude/agents/`, and three hooks in `.claude/settings.json` — `SessionStart` (prep), `PostToolUse` on `Edit|Write` (fast anti-pattern check on the UI file just edited, injected back as context to triage), and `Stop` (full-rule "deep pass", 30 s budget). All three call the skill's `scripts/impeccable` launcher, which fetches and sha256-verifies its engine binary into `~/.impeccable/bin/<version>/` on first run (about 1.5 s, once per container). Run `.claude/skills/impeccable/scripts/impeccable detect <file>` for a manual scan.

It was **not** installed with `npx impeccable install`: in Claude Code cloud sessions the installer's signed-bundle download goes through `github.com/pbakaus/impeccable/releases/latest`, which the egress proxy blocks (HTTP 403), so `npx impeccable install` / `update` fail there. The files were instead copied from upstream's own committed Claude build (`.claude/skills/impeccable`, `.claude/agents/impeccable-*.md`, and the `hooks` block of its `.claude/settings.json`) at commit `0d6b47e`, skill/engine version 0.1.8. To update in a cloud session, shallow-clone upstream and re-copy those same three pieces; locally, `npx impeccable update` should work. To silence the hooks without uninstalling, delete the `hooks` key from `.claude/settings.json`.
